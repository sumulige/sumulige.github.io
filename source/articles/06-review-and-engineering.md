**6. 审核结论与工程化边界**

[阅读入口](README.md) · [上一篇](05-code-and-reproduction.md) · [引用与产物总目录](07-reference-and-artifact-register.md)

已经能运行计算，不等于已经得到可直接使用的教练系统。本篇沿着[validation.md](../analysis/validation.md)和[decision.md](../analysis/decision.md)，解释当前证据允许声明什么，以及哪些问题仍需研究。

**6.1 六项声明逐项对照**

| 编号 | 要判断的内容 | 当前状态 | 能够回查的依据 |
|---|---|---|---|
| C1 | 指定候选满足所检查的 WF-net 性质 | VERIFIED | 手工推导、完整枚举、两个预设反例 |
| C2 | 候选能表达公开案例中的部分工作 | PARTIAL | E1–E5 到模型的映射；A1–A4 尚待实证核对 |
| C3 | 对完整教练职责的覆盖程度 | PARTIAL | 目标、资源、决定权等尚未充分表示 |
| C4 | 能预测新案例的实际行动 | UNKNOWN | 没有留出案例，也没有明确分支选择机制 |
| C5 | 使用它能改善训练或比赛表现 | UNKNOWN | 本轮没有效果或因果研究 |
| C6 | 可以直接作为产品架构 | UNKNOWN | 尚未验证实际使用情境、接口、权限和异常处理 |

PARTIAL 表示支持或覆盖不完整，不表示已经证明整个声明成立。尤其不能把 C3 改写为“完整流程已经建模，只剩实现”。

**6.2 一个结论应怎样逆向审核**

以“当前模型满足规范完成”为例，可以沿以下顺序核对：

1. 在[原始输出](../evidence/model-check.json)找到 `candidate.checks.proper_completion`，确认为真。
2. 核对 `complete_enumeration` 为真，再查看全部 `states`：只有规范终态包含 p7。
3. 在[代码](../analysis/verify_model.py)检查 `bad_completion` 的构造，确认它确实寻找带终点 token 的非规范标识。
4. 在[模型说明](../analysis/model.md)确认规范终态的含义是本次观察归档。
5. 回到 A3，确认归档没有被解释成恢复成功。

这条审核路径允许证明 C1 中的一项性质，不能证明 C5。即使前三步完全正确，最后两步仍可能暴露语义被扩大解释的问题。

若审核“模型解释了真实教练决策”，路径必须继续追到案例当时的信息、备选、行动理由和时序。当前资料缺失的部分，应停止相应声明，而不是用更多代码代替。

**6.3 完整职责还缺哪些内容**

| 职责 | 当前候选怎么表示 | 尚未表示或没有证据的内容 |
|---|---|---|
| 目标与方向 | 没有单独表示 | 目标协商、优先级、目标冲突与变化 |
| 资源与环境 | 没有单独表示 | 人员、场地、时间冲突怎样改变可选行动 |
| 沟通与决定权 | 反馈被汇总为一个转移 | 谁提供信息、谁决定、分歧如何解决 |
| 训练与比赛组织 | 当前方案到执行的粗粒度关系 | 具体任务、偏差、比赛情境 |
| 观察与调整 | 反馈及再次调整的回路 | 状态判断、触发条件、信息不足 |
| 评价与学习 | 本次观察归档 | 如何评价一次决定、怎样改变下一次规则 |

这份对应表沿用[标准与方法筛选记录](../findings.md)的职责范围，没有新增评分或通过门槛。给图增加六个职责名称并不能补上缺失的条件关系。

**6.4 为什么六阶段记录可以通过，而适用性仍未知**

[study.json](../study.json)记录本研究的材料、审阅依据和阶段关系。它组织的是研究工作，与教练专业框架中的六项职能属于不同层次。

| 研究阶段 | 本轮形成的对应产物 | 通过意味着什么 |
|---|---|---|
| 1 澄清问题 | intent、question | 研究对象和用途已经写明 |
| 2 核对证据 | source-audit、findings、public-case | 对本轮有限问题有可定位来源，缺口已说明 |
| 3 制定方案 | protocol | 方法、失败方式和停止条件事先明确 |
| 4 执行研究 | model、model.json、代码、results、机器输出 | 声明的计算已执行，偏离和结果已记录 |
| 5 验证适用性 | validation | 逐项说明证据支持什么、不能支持什么 |
| 6 决定转化 | decision | 决定继续研究，并明确不据此启动工程化 |

第 5 阶段通过，可以意味着“已准确识别多个 UNKNOWN，并没有作出相应声明”。它不要求所有用途都被证实，也不会把未知自动改成已验证。

早期[门禁回执](../evidence/gate-check-before-public-case.json)显示第二阶段因案例缺口而 BLOCKED。用户随后选择先从公开案例开始，研究取得相应材料，并把首轮范围限定为有限流程表达。[最终回执](../evidence/gate-check.json)记录六阶段 PASS。得到公开案例解决了这个有限范围的必需缺口，原始逐次决策材料不足仍然存在。

检查器的范围包括文件可用、定位摘录和已记录的审阅；其自身说明也排除了科学真伪及授权身份的自动认证。因此，回执不能替代原始材料审查，也不能作为工程发布批准。

**6.5 下一轮怎样真正检验假设**

下一轮仍可以从公开材料开始，但需要先固定当前假设，再选择未参与构建的案例。以下是检验方向，没有设定准确率、样本量或新的验收阈值。

| 待检验对象 | 新材料可能提供的反证 | 怎样记录 |
|---|---|---|
| A1 的汇合前提 | 某项分析未完成时已形成组合方案 | 保留当时信息和时间点；判断前提是否过强 |
| A2 的原子化 | 多次信息到达之间已经发生行动改变 | 分别记录观察和行动，不直接压缩成一个事件 |
| A3 的观察窗口 | 关键决策跨越多个窗口 | 明确观察边界是否切断必要关联 |
| A4 的选择未知 | 材料提供了真实备选、理由及选择时点 | 检验可否形成条件规则，保留多个合理解 |
| 完整职责覆盖 | 资源、授权或目标冲突决定了行动 | 判断是否需扩展研究对象，而非只加节点名称 |

如果新材料只有事后概述，无法判断某项前提是否成立，应记录“资料不足”，不能直接判为支持或反驳。若出现明确不相容，应保存反例，再决定修订或舍弃假设；事后修改必须与原版本区分。

**6.6 什么时候才需要进一步考虑 POMDP**

若材料表明决定依赖对不可直接观察状态的判断，而且获取信息本身会改变后续选择，可以评估部分可观测模型。M2 提供这种表达的通用方法，没有替本研究确定状态、参数或价值取舍。[M2 原始论文 §3.1–3.4](https://people.csail.mit.edu/lpk/papers/aij98-pomdp.pdf)

令 \(b_t(s)\) 表示根据截至 t 的信息，对状态 s 的信念。给定状态转移模型 T 与观测模型 O，一种离散更新分两步：

\[
\bar b_{t+1}(s')=\sum_s T(s'\mid s,a_t)b_t(s),
\]

\[
b_{t+1}(s')=\eta\,O(o_{t+1}\mid s',a_t)\bar b_{t+1}(s').
\]

第一步预测行动之后的状态分布，第二步用新观察调整，再通过 \(\eta\) 归一化。如果当前模型给观察分配的总概率为零，就不能正常按此式归一化，应检查模型与信息是否不相容。

数学形式成立的前提仍包括状态与转移假设。本轮没有估计 T、O 或信念分布。若进一步求最优策略，还需要明确回报、时间范围和风险取舍；那些值不是从流程图自动推出的。

现阶段可以继续用简单条件规则和状态转移关系比较解释能力。只有材料需要更复杂表达，才有理由增加复杂度。

**6.7 工程化前需要形成的具体方案**

当前转化决定是保留候选、继续案例验证。后续若要采用它，需要先明确如下对象，供人类确认。本表是准备方案的内容，不是已经批准的产品架构或验收标准。

| 需要明确的对象 | 需要写清的内容 | 相应证据 |
|---|---|---|
| 用途 | 记录、复核、解释、建议或其他具体用途 | 实际用户情境及可接受的声明范围 |
| 模型范围 | 项目、人群、时间尺度、职责覆盖及保留假设 | 标准采用范围和新案例核对 |
| 输入输出 | 信息从哪里来、何时可用、缺失怎样表示 | 实际数据和工作过程 |
| 人员与权限 | 谁提供、复核、修改和最终决定 | 明确的责任与授权安排 |
| 异常处理 | 延迟、缺测、冲突、无法继续和退出 | 真实情境或经确认的端到端场景 |
| 验收与回退 | 怎样证明软件忠实实现模型，何时保留人工判断 | 可复现运行产物及对应审核 |

软件端到端检查可以验证实现一致性，训练效果需要另一层研究。实际架构、业务数据模型、外部依赖、隐私权限及质量门槛的采用，仍应提交具体方案确认。本轮没有接入真实运动员数据或执行训练干预。

**6.8 自检与提示**

1. 六阶段 PASS 是否表示工程化获批？——不表示；当前决定明确继续研究。
2. 新案例不符合模型时，是否应马上添加一个特例？——先记录冲突，再判断假设、粒度或资料缺口。
3. 为什么重新跑一次得到相同结果还不够？——它支持计算可重复，不能新增真实决策或效果证据。
