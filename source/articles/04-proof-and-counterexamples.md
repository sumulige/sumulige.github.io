**4. 逐步推导与形式验证：八个状态、九条边从哪里来**

[阅读入口](README.md) · [上一篇](03-model-and-assumptions.md) · [引用与产物总目录](07-reference-and-artifact-register.md)

本篇将[model.md 的直接推导](../analysis/model.md)与[model-check.json 的实际输出](../evidence/model-check.json)逐项对照。输入、预期、失败方式先保存在[protocol.md](../protocol.md)中；这里展开的是既有结果，不是根据结果重新挑选的检查项目。

**4.1 先检查结构，再检查运行**

工作流网 WF-net 对入口、出口及节点之间的贯通关系有结构要求。本例检查入口没有入边、出口没有出边，并且所有位置和转移都位于从入口通向出口的有向路径上。结构合格之后，还要检查 token 实际移动时是否能正确完成。[方法来源：M1 §5.1–5.2](https://www.vdaalst.com/publications/p53.pdf)

图上的连接路径不等于可执行路径。一个转移可能有来自两个位置的输入；单独看有向连接，可以找到经过它的路径，但实际发生仍需要两个输入同时满足。反例 A 还说明，结构贯通也不能排除完成后的残留工作。

**4.2 列出全部可达状态**

从只在 p0 有 token 的初态开始，每次尝试全部已启用转移。下表的编号与当前 JSON 输出一致：

| 输出中的状态 ID | 有 token 的位置 | 可发生转移 | 下一状态 |
|---|---|---|---|
| m0 | p0 | t0 | m1 |
| m1 | p1、p2 | t1 或 t2 | m2 或 m3 |
| m2 | p2、p3 | t2 | m4 |
| m3 | p1、p4 | t1 | m4 |
| m4 | p3、p4 | t3 | m5 |
| m5 | p5 | t4 | m6 |
| m6 | p6 | t5 或 t6 | m5 或 m7 |
| m7 | p7 | 无 | 规范终态 |

所有下一状态都已出现在表中。因此，从初态出发不会因再发生一次已启用转移而跳出这个集合。这给出可达集合的闭合检查。

完整的九条边如下，可直接对照 `cases[0].edges`：

```text
m0 --t0--> m1
m1 --t1--> m2
m1 --t2--> m3
m2 --t2--> m4
m3 --t1--> m4
m4 --t3--> m5
m5 --t4--> m6
m6 --t5--> m5
m6 --t6--> m7
```

状态 ID 是本次遍历时分配的标签。另一个模型中也叫 m7 的状态，未必具有同样的 token 分布。审核时要看 `states[].tokens`，不能只比编号和数量。

**4.3 三项性质分别怎样证明**

本轮使用 M1 §5.2 Definition 7 的三个性质。下面把它们写成适合逐项审核的形式。[原始定义](https://www.vdaalst.com/publications/p53.pdf)

1. **仍有完成路径。** 对每个可达标识 \(M\)，存在一个可执行转移序列 \(\sigma\)，使 \(M\xrightarrow{\sigma}M_f\)。在当前图中，m0 至 m6 均可沿着后续任务到 m6，再选择 t6 到 m7；m7 已经是终态。程序采用从 m7 沿反向边寻找所有前驱的办法，得到全部八个状态。
2. **规范完成。** 如果某可达标识在 p7 有 token，它必须恰好等于规范终态 \(M_f\)。表中只有 m7 含 p7，且其他位置为空。因此没有归档后残留 token 的状态。
3. **无死转移。** 每个已声明转移都至少能在某条从初态出发的执行路径上出现。路径 t0 → t1 → t2 → t3 → t4 → t6 覆盖除 t5 外的转移；在归档前增加一次 t5 → t4 即可覆盖 t5。

第二项允许研究实例以归档结束，没有定义训练是否成功。第三项只证明每项任务存在可执行机会，并不要求每次运行都发生全部任务。

**4.4 用不变量作另一项核对**

以 \(m_i\) 表示位置 \(p_i\) 的 token 数，取权重向量

\[
w=(2,1,1,1,1,2,2,2)^\mathsf T.
\]

前一篇的净变化矩阵满足 \(w^\mathsf TC=0\)。因此，每次转移都保持 \(w^\mathsf Tm\)，从初态得到：

\[
2m_0+m_1+m_2+m_3+m_4+2m_5+2m_6+2m_7=2.
\]

逐列核对并不复杂：t0 消耗权重 2、产生 1+1；t1、t2 各为 1 换 1；t3 为 1+1 换 2；其余三个转移都是 2 换 2。

正权重与固定总和限制了各位置可取得的 token 数，因此为有界性提供直接依据。但这个等式本身仍允许某个权重为 1 的位置放两个 token。**各位置至多一个 token**是由完整可达集合进一步核对得到的，不能仅凭这条等式宣布。

程序的 `declared_invariant_preserved_by_each_transition` 检查的是给定权重是否在每个转移下保持；它没有自动发现新的不变量。这个额外结果也不是脚本判定 `PASS` 的独立必要条件，判定规则见第 5 篇。

**4.5 为什么正确完成仍不代表必然结束**

当前图存在：

\[
\{p_5\}\xrightarrow{t_4}\{p_6\}\xrightarrow{t_5}\{p_5\}.
\]

如果每次到达 p6 都选择 t5，过程可以一直重复。三项性质中的第一项是“每个状态存在完成路径”，其量词不是“所有路径最终完成”。

模型没有等待时间、最大重试次数或保证选择出口的规则。若实际应用要求按时结束，需要额外的情境和结束条件证据；不能为了获得漂亮结果而默默加入一个次数上限。

**4.6 反例 A：结构贯通，但结束时有残留**

预设修改只改变 t3 的输出：由 `{p5}` 改成 `{p5,p4}`，输入仍为 `{p3,p4}`。因此 t3 需要 p4 的 token，但发生后又把它放回。这也是为什么净变化为零不能解释成不需要输入条件。

沿着原候选的完成路径执行后，得到 `{p4:1,p7:1}`。此时已经没有 p3，残留的 p4 无法再与 p3 一起通过 t3 被消耗。原候选的规范终态仅允许 p7，因而不可达。

实际输出显示：仍有 8 个状态、9 条边，结构仍是 WF-net；完成路径性质与规范完成性质均失败，无死转移仍成立。声明的权重不变量也被 t3 打破：输入权重为 2，输出权重为 3。

状态数、边数和结构合格，都不足以单独证明动态运行正确。错误见证可以在 `counterexample_A.proper_completion_counterexample` 及其对应 `states` 中核对。

**4.7 反例 B：删除出口后，某个命题会空真**

第二个修改删除 t6。p7 不再可达；实际图有 7 个状态、8 条边，结构和完成路径性质失败。

`proper_completion` 却返回 `true`，因为没有任何到达 p7 的状态能够违反“到达时无残留”。这是逻辑上的空真，不是一次成功完成。另一方面，`no_dead_transitions` 只检查模型里仍然存在的六个转移；被删除的 t6 不再属于待检查集合，所以它仍可为真。

该反例的权重不变量仍成立，也再次表明不变量不能代替终点可达性。

|---|---|---|---|---|---|---|---|

这三个对象只检查一个有限研究候选及两种指定形式错误。它们没有证明检查器对任意复杂 Petri 网都正确，也没有形成独立研究审查。

**4.9 自检与提示**

1. 为什么两份输出都是 8 个状态、9 条边，却只有一份通过？——状态中的 token 分布和完成性质不同。
2. 反例 B 的规范完成为真，为什么整体失败？——出口不可达；不能只选择其中一项性质报告。
3. 为什么发现无限回路却仍可 `PASS`？——所检查的定义要求存在完成路径，不要求所有无限选择都结束。
