# 周三补上的周一骑行，能否用于周二的判断？

周一骑了一次车，周二早晨系统给出恢复建议，周三才上传完整活动。如果今天回看周二的建议，能不能把这次活动补进去？答案取决于要回答什么。复查系统周二为何作出那个决定，需要恢复它当时可见的信息；研究周一的实际运动与后来反应，则可以审查周三补得的记录。两个问题使用同一场骑行，但信息边界不同。

这一区别比把所有日期统一成一种格式更早。先说明记录代表什么，再判断时间字段是否足够。[Q078原答](#/article/series-guide?section=publication)把补录对因果推断的影响说得过于普遍，本篇将它拆开。

## 发生时间、可用时间与修订时间

事件时间描述骑行何时发生。可用时间描述指定的人或系统何时能够取得这条信息。修订时间描述某个版本何时替代了此前的记录。三者可以相同，也可以相隔几天。

可用性必须说明主体。骑手周一就知道自己骑过车，教练可能当晚收到口头报告，平台周三才收到文件。因此平台上传时间不能替代所有人的知识时间。如果系统周二已读到手工摘要，重放时就应使用那份摘要，而不是假设它完全不知道这次骑行。

Fonseca的2026年预印本把防止前视信息泄漏表述为一种非干扰性质：只改变决策之后才可用的信息，先前输出应保持不变。这是检查历史重放的有用思路；其证明与分析有程序语言和可用性假设，不能自动覆盖任意程序，更不能验证源时间戳真实。当前核对到的是预印本，本批没有运行作者工件。[论文全文](https://arxiv.org/html/2607.04958v1)

考虑一组人工版本记录。负荷数字只有演示意义：

|记录|实际发生|本系统可用|数值|
|---|---|---|---:|
|A初版|周一18:00|周一20:00|40|
|A修订版|同一场周一骑行|周三10:00|100|
|B初版|周一19:00|周三10:00|30|

以周二08:00为截止，系统只能选择A初版40。如果把周三的两个值改成300和90，周二重放仍应是40。删除周三版本，也仍是40。三个世界的最终已记录合计却分别为130、390和40；把这些最终合计直接交给周二的决策，就使它依赖了之后的信息。[完整输入与结果](#/article/series-guide?section=publication)

这里没有把当时不可见的B当成已知零。没有记录只说明缺少记录，不能证明没有骑行。最终已记录合计也未必等于真实完整负荷；上传遗漏、设备错误和重复活动仍可能存在。

## 事后补得的信息不等于未来发生的信息

研究者周五分析周一的骑行，可以使用周三取得的文件来重建过去暴露。这样做是否合适，取决于文件真实性、缺失方式、修订过程和具体研究设计。若上传只发生在疲劳较重时，选择性记录仍可能造成偏差；若靠回忆补录，测量误差也需要处理。

这与另一种问题不同：用周四是否完成训练来定义周一已接受某策略的人，再从周一开始统计结果。后者把未来发生的行为带入基线分类，可能改变分组所需的生存或持续参与条件。后来获得过去的信息，与用未来事件定义过去的组别，不能混为一谈。

Hernán等讨论目标试验时，强调资格、策略分配与随访起点应相互对齐，也明确指出正确对齐并不消除混杂。本次通过原站索引读取相关段落和结论，未把受限访问说成逐页通读。这一方法原则可用于检查问题定义，但尚未验证某个训练模型。[原论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC5124536/)

例如要估计周一训练对周二疲劳的影响，至少需要明确训练指什么、疲劳何时测、哪些因素同时影响训练选择与疲劳，以及谁有机会进入分析。把时间格式全部改正确，仍然不能让这些条件自动成立。

## 回到系统用途

同一条修订记录可以支持几个不同视图：当时所见、现在认为发生了什么，以及修订如何改变先前结论。三者都可以有用，只要名称和计算对象明确。本文没有要求采用某种数据表结构；保留这些区别是研究解释，实施架构需要另行决定。

同样，没有证据证明所有系统都只需重算最近3—7天。必要范围依赖实际上传延迟、历史修订、下游计算和研究目的。长期依赖可能超出一个固定窗口；一个只回答当日展示的问题也可能不需要全量重算。

本批能确认的是人工例子中的版本依赖，以及原答需要保留的用途差别。真实系统是否正确重放、某次补录是否改变因果估计，仍需实际记录与指定分析。接下来还要处理另一层问题：事件时间本身是否被正确表示，以及当地时间是否能代表生理时间。
