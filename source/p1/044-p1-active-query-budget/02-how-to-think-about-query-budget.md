# 每周最多问两次，有什么依据

周二的一次骑行出现了值得确认的片段，系统想问一句；周末可能还会有更重要的赛事。如果用户只愿意接受一次主动询问，现在就用掉，还是留到周末？

这个问题不能只靠“每周有几次高强度训练”回答。训练次数描述身体承受的刺激，提问次数描述交互安排。两者没有必然的一比一关系：一次活动可能包含多个不清楚的事实，一次很轻松的骑行也可能暴露设备问题。Q784原答给出的每周1—2次、每题10—15秒，可以作为待检验的设计想法；原答也承认没有关于这一具体骑行场景的专项实验。[原题与原答](#/article/series-guide?section=publication)

## 现有研究支持考虑负担，不能直接给出“两次”

一项2024年的生态瞬时评估随机试验，在28天内比较了每日2次与4次、每次15题与25题等设计因素。485人随机入组，排除通知技术异常及完全未答者后，411人进入分析；参与者有经济补偿。未调整模型没有发现这些设计因素对完成率的显著影响，但每日4次组更容易认为次数太多。[Businelle等，2024，方法、表4及参与者感受](https://www.jmir.org/2024/1/e50275/)

这项研究提醒我们，完成率与负担感不是同一个结果。不显著也不证明两种安排等效。它研究的是有补偿的手机评估，任务、频率、人群和时长都不同于长期骑行产品，因此不能换算为“每天可以问四次”或“每周必须少于两次”。更不能从完成率推断答案准确或训练决策更好。

即时自适应干预框架区分了决策时点、用户当下接收和处理信息的能力，以及选择不提供干预的情况。它有助于组织问题，但并没有给本题提供最佳周频率或晚间推送的实证答案。[Nahum-Shani等，JITAI设计框架](https://pmc.ncbi.nlm.nih.gov/articles/PMC5364076/)

## 多等一会儿，可能更容易回复，也可能来不及使用

假设某个问题的回答正确率为90%，两种目标状态原本各占一半，提问成本为0.05单位。沿用[上一篇的有限例子](#/article/p1-044-01-which-question-is-worth-asking)，回复率会影响预期决策收益。

|时机|设定的回复率|能否赶上本次决策|扣成本后收益|
|---|---|---|---|
|立即问|30%|能|0.07|
|稍后问|90%|能|0.31|
|稍后问|90%|不能|−0.05|

如果稍后既容易回答，又没有错过需要使用信息的时刻，等待在本例里更好。但当这个决定已经作出，稍后答案不能倒过来改善那次选择。第三行只计本次决策的用途，并未评价答案对未来学习的价值。

这里的回复率是设定，不是对赛后缺糖、疲劳或晚间注意力的测量。不能用这个例子宣布“刚骑完不要问”或“晚上一定更好”。实际需要同时观察用户可接受的时段、答案延迟、信息可用期限，以及问题是否仍值得问。

## 有正收益，也不一定应该立刻花掉唯一一次机会

再设一个两时点问题。当前询问的预期净价值是0.12；未来可能出现净价值0.30的重要问题，也可能只有净价值0.02的问题，两种情况各占一半。所有数值已扣除成本，彼此可加，未来具体情况尚未揭晓。

如果现在只剩一次提问机会，立即问的价值是0.12。保留机会，稍后根据实际出现的问题再问，期望价值为0.5×0.30+0.5×0.02=0.16，因此等待更好。当前问题确实有价值，但它占用了一个可能用得更好的机会。

这也不意味着总要等。若未来重要问题出现概率只有20%，等待价值变成0.2×0.30+0.8×0.02=0.076，此时先问更好。若可用次数为两次，本例可以在两个时点都问；它说明预算影响机会选择，却没有证明用户应该允许增加次数。

还有一个常见评价陷阱：假装系统在周二已经知道周末会发生什么。若提前知道未来具体值，在上述各占一半的情形中，就能在未来重要时留次数、未来不重要时现在问，平均得到0.21。真实在线策略只能依据当时已知的信息，不能把这个事后上界算成自己已经达到的能力。

本批对三种未来概率和两种预算进行了比较，最终核验用39个不预知未来的策略作枚举对照。实际产品还可能存在问题重复、互补、疲劳和概率估错；本例没有覆盖这些复杂性。相互关联问题的顺序可参阅[既有提问顺序研究](#/article/series-guide?section=publication)，不能把单题价值不加条件地相加。

## 两道题，未必只有两次打扰

“每周最多两次”还需要说明在计什么：两道不同问题、两次推送尝试，还是两次成功回答？如果用户没有回答，重发算不算一次？

用一个纯计数例子说明。共有两道题，每次尝试独立以40%概率获得回答，答完后立即停止该题的后续尝试。

|每题最多尝试|最多通知数|平均尝试数|平均答完题数|
|---|---|---|---|
|1次|2|2|0.8|
|2次|4|3.2|1.28|
|3次|6|3.92|1.568|

第三行仍只有两道题，却允许最多六次通知。平均3.92次是很多同类情境的平均，不是一次能发小数条通知。实际回复也不会保证独立：反复打扰可能改变之后的响应。这张表只证明预算分母必须写清，没有推荐重试。

因此，只报“收到了多少答案”会漏掉用户经历了多少次尝试；只报“平均答题耗时”也可能漏掉阅读、回忆、切换任务以及纠错的负担。少量问题可以很难回答，多道简单问题也可能在不合适的时刻造成明显打扰。

## 预算是允许的上限，不是必须完成的配额

如果没有值得问的问题，保留次数是合理结果。[上一篇](#/article/p1-044-01-which-question-is-worth-asking)的构造已经给出一个有少量信息但净价值为负的条件。反过来，即使模型算出正收益，也不能自行突破用户明确的通知限制。收益是在允许范围内比较选择的依据，不是扩大授权的理由。

预算耗尽或用户不回答时，应保留基于现有证据形成的判断及其不确定性。缺少一条标签不等于已经确认“是比赛”，也不意味着必须退回最初的宽先验。是否暂缓某种更新、保留待确认状态，属于需要具体设计的处理政策，不能直接用“保守”替代对后果的解释。

要决定实际预算，接下来需要的是目标场景中的证据：问题是否被理解、多少通知实际送达、哪些人回应、回答是否可用、是否赶上决定、负担是否累积，以及最后是否改善了相应任务。可以比较有明确用途的候选安排，但实验、推送和质量标准都需要另行形成具体方案。本批没有替产品选定每周次数、秒数或通知时点。
